# Architecture

Voldiq has one reusable engine crate, a desktop adapter and a separate headless CLI/MCP adapter. The headless binary depends on `voldiq-core` and the official MCP Rust SDK, without Tauri or a renderer.

## Authorized headless services

`agents` owns connection policies and digest-only credential storage. Windows authorization opens metadata handles from the volume root to the target, refuses reparse points and ambiguous path syntax, pins ancestor names and compares native root identities. Capabilities and credentials are rechecked on every call. Exclusions also match directory identity so a renamed excluded directory does not become an allowed metadata path.

`jobs` stores bounded scan status and cancellation in SQLite. An OS-released operation lease retains the `scan.lock` filename and serializes scans and file operations across desktop and headless processes using the same state directory. Interrupted jobs are marked when the next lease is acquired and are never retried automatically. The desktop retains its existing `IndexId` publication rules; its in-memory progress is not yet mirrored into the durable job table.

`service::AgentService` scans only permitted roots with verified exclusions, persists compact snapshots through the existing store and serves bounded queries from one cached index. Connections can read shared desktop/agent snapshots only after a small scope query verifies native root identity and sufficient exclusion coverage. Unauthorized roots fail before loading the index. Filtered history pages use one SQLite read view and expose no unfiltered totals. Jobs remain owner-scoped. `voldiq-headless` implements versioned CLI output and twenty-two `rmcp` stdio tools: sixteen analysis and six exact recycling-plan lifecycle tools, with bounded input/output and worker concurrency. Human provisioning and approval use separate desktop/native channels. Agents cannot provision, rotate or approve through their transport. Native provisioning and the complete elevated agent/Shell route retain manual acceptance; transfer/restore plans remain pending. See [MCP](MCP.md) and [remaining coverage](WORKBENCH-COVERAGE.md).

## Engine

`scanner` performs an iterative directory walk with cancellation and bounded metadata work. Manual concurrency accepts one to eight workers. Automatic mode uses up to two workers when Windows reports no seek penalty, and one when a seek penalty is present or unknown. It excludes requested paths and records reparse points without following them.

The index stores compact 32-bit node IDs, parent IDs and names. Full paths are reconstructed only when requested. Each insertion propagates its totals through existing ancestors, so partial directory totals are immediately consistent. Allocation deduplication uses volume identity and file identity. Logical totals retain each path name.

Queries return at most 500 entries. The frontend renders at most 80 table rows per virtual window. Overview requests up to 250 direct children, plus the eight largest direct entries beneath each of up to twelve visible directories. The descendant pass checks cancellation every 256 index entries. Unrepresented bytes appear in a smaller-items region linked to the complete virtual list.

Queries filter references into the in-memory index, partition at the requested offset and limit, then sort only the returned page. They retain exact deterministic ranking without sorting every match. Empty searches avoid allocating lowercase names, ASCII name comparisons allocate nothing, and Unicode names retain lowercase ordering. Root scope checks are constant time. Progress is emitted at initialization, the first insertion, every 100 ms and completion.

## Desktop adapter

Tauri exposes volume discovery, native folder selection, scanning, cancellation, bounded index and duplicate queries, details, file types, analysis issues, Explorer reveal, history, developer analysis and confirmed cleanup. Fixed Windows launch commands open Storage settings and the Recycle Bin. No arbitrary frontend filesystem API or shell command is exposed.

Scanning and queries run in background tasks. The engine publishes one shared index behind `Arc<RwLock<Index>>` before initial progress. Filesystem calls happen outside the write lock; inserting entries and updating ancestors uses a short write section. Queries hold a read guard and return bounded results. The interface refreshes measured partial results at most once per second, plus terminal progress, without polling. A second scan cannot start until the first releases the active operation slot.

## Interface

Svelte owns interaction state, preferences and bounded query results. A custom squarified treemap redraws when geometry, selection or hover changes. There is no persistent animation loop or idle polling. Pointer hierarchy navigation can schedule a finite 160 ms map transition; it cancels on new input, replacement, resize, reduced motion, hiding or unmounting. Layout uses Windows system fonts and local artwork.

## Duplicate analysis

`duplicates` filters unique sizes before content reads, samples the first and last 4 KiB for large files, and fully hashes matching samples with a reusable 64 KiB buffer. Small files are read once. Candidate identities exclude hard-link aliases. Windows content handles allow shared readers while excluding writers and deletion, and do not follow final reparse points. Cache stamps include identity, length, modification time and native change time. Hashing validates the opened handle again after reading. Cancellation is checked between candidates and buffer reads.

Duplicate results retain the exact shared scan index that produced their IDs. Groups and members use bounded pages. One active-operation slot prevents scanning and hashing from competing. The cache has a 250,000-identity cap and persists in snapshot database schema 5. Duplicate analysis lazily loads fixed-size identity, stamp and digest fields, then transactionally replaces the bounded table. No paths or file content are stored. It still opens the real file and validates its complete stamp before accepting a hit. Invalid rows are ignored before hashing; database failures become reported analysis issues and ordinary hashing remains available. Cancellation rolls back cache replacement. Cache memory belongs to the operation and is released afterward.

## Snapshot history

The bundled SQLite database uses WAL, foreign keys and transactional schema initialization. A root key combines the native root path, filesystem identity and exact exclusion coverage. Stable paths store native name bytes and parent IDs. Entry versions use half-open snapshot intervals; unchanged captures do not copy every entry. Snapshot deletion retains versions required by surviving captures, and compaction checkpoints the WAL and vacuums the database.

Snapshot schema 8 adds per-group retention preferences and transactional history/configuration revisions. A desktop review retains at most 100 exact oldest captures; its fingerprint binds their metadata, the group, preference and revision. Apply rechecks that fingerprint under an immediate transaction and the shared native operation lease, preserving the configured newest captures. Cancellation/failure rolls back the batch and its interval garbage collection. Preferences default to Keep all; saving one does not run retention. No CLI/MCP history-removal endpoint exists. These revisions detect application-managed changes, not privileged tampering with local state.

Schema version 4 adds per-capture developer-cache evidence referencing those stable paths. It stores tool/category labels only for indexed directories, including an indexed root beneath a known cache. Historical queries reconstruct cache scopes from saved node IDs and never resolve current tool settings. Index loading reads entries and cache evidence in one SQLite transaction. Live scan and NTFS replay indexes start without historical cache evidence.

Schema version 5 adds the independent bounded duplicate-hash table. Versions 0 through 4 migrate transactionally without rewriting stored snapshot entries. Older executables that support only schema 4 cannot reopen an upgraded database.

Loading reconstructs the Rust index and validates parent order, node limits, filename components and checked integer conversions. Snapshot comparisons page actual additions, omissions and changed directory totals. Incomplete coverage never confirms missing entries as deleted. Database work runs in blocking tasks. The active-operation gate prevents capture and loading from racing a scan or duplicate analysis. Capture/loading commands acknowledge their operation IDs through channels so History can use the existing owner-specific cancellation endpoint. Loading checks cancellation before its read transaction, between rows and before returning. Final publication holds the active-operation mutex while checking cancellation and swapping the loaded index, so publication completes before a cancellation acknowledgement or retains the previous analysis. Capture keeps its transactional pre-commit check and returns its committed ID on success.

History invalidates late channel acknowledgements by action generation and cancels owned work on unmount. Its Cancel control ends when the native result arrives, before frontend refresh or adoption. Removed-button focus returns to the original connected trigger when focus has not moved elsewhere. Cancellation remains cooperative: an already running SQLite call or connection-mutex wait must return before the worker finishes. Comparison, deletion and compaction do not use this capture/load control.

## NTFS scanning and refresh

Eligible volume-root scans try native NTFS enumeration before directory walking. Capability failures fall back before publishing non-root IDs. Incremental refresh checks the saved volume and journal checkpoint, constructs a new candidate index, and publishes only after final continuity checks. Invalid continuity or unsupported changes trigger resynchronization; cancellation keeps the previous index. Raw-volume acceptance on this host remains unverified. See [NTFS scope](NTFS.md).

## Cleanup

The backend owns a single-use plan tied to the live index. Preview validates exclusions, native identity and metadata; execution pins ancestors and files, and duplicate cleanup also retains a freshly verified copy. Advanced permanent removal commits per-item intent to a separate exclusive SQLite journal before native handle-based disposition. Result-write failure stops further work. On restart, in-flight items become unknown and are never retried automatically.

Desktop recycling and recorded-item restoration are enabled under the earlier product acceptance. The historical combined privileged diagnostic was not rerun, so activation does not establish that diagnostic as passing. Agent execution adds an exact manifest, independent live human grant, repeated authorization and retained native evidence before desktop dispatch. The retained fixture proves helper refusal and durable results; complete elevated agent/Shell acceptance remains manual. The [recycling transaction design](RECYCLE-TRANSACTION.md), [cleanup evidence](CLEANUP.md) and [agent plan boundary](AGENT-PLANS.md) describe those guarantees and limits.

The overview queue normally keeps only the latest request. Explicit folder navigation now owns a short frontend refresh interval while its details and overview are pending. Scan-progress refreshes defer during that interval and coalesce into one refresh of the committed destination afterward. A stale navigation completion cannot release a newer owner, and obsolete navigation overview replies or errors cannot commit after another interaction. Interaction invalidation clears abandoned ownership.

This prevents a progress update for the old committed scope from superseding a pending folder transition. It adds no polling or visible copy. Native index replacement has its own ownership rule below. ## Index publication ownership

Each loaded `SharedIndex` has an opaque `IndexId` paired with its Arc and analysis date under the engine mutex. Updating the date for the same Arc preserves its identity. Replacing or clearing the publication invalidates that identity, including when a previously removed Arc is loaded again. Terminal scan events capture identity and date together before releasing operation ownership.

Every node- or duplicate-group-scoped IPC request carries the identity of its originating analysis. The native adapter validates it before interpreting local IDs. Cancellable reads also check the captured Arc before returning. Cleanup execution retains its existing one-use plan and exact-Arc check. Snapshot database IDs and cleanup journal receipt IDs have independent ownership.

The frontend captures identity when scheduling queries and discards late management replies after replacement. Adopting a new publication clears selection, details and folder scope, cancels obsolete queries and remounts index-bound views. An unscanned cleanup rule may request static metadata with no identity; it cannot resolve indexed files that way.

The retained native case scans two real folders whose local node IDs overlap and proves that the first identity cannot resolve the second index. The frontend case verifies a delayed IPC reply against an injected transport. Both counterexample mutations fail their retained case, and the restored source passes the [complete source gate](../benchmarks/project-verification-index-ownership-20261031.json). These checks add no declared tests or native interaction acceptance. See [ownership verification](../benchmarks/index-ownership-20261031.json).

The [current native preview](../benchmarks/native-index-ownership-preview-20261031.json) opens a responding Voldiq window from the rebuilt executable. Its receipt records the executable and frontend hashes. The previous owned preview closed normally and its 12,699,648-byte executable was removed. No visual or pointer/keyboard acceptance is inferred from this metadata.

## Standalone interface loading

Optimized native binaries must enable Tauri's production protocol. The project `production` feature forwards `tauri/custom-protocol`, and a compile-time guard rejects a non-test optimized binary in Tauri dev mode. The Tauri CLI production build also enables the underlying protocol. A direct Cargo `--release` flag alone is insufficient.

The `--verify-embedded-ui` diagnostic constructs the compiled context and exits before application setup. It reports decoded runtime asset lengths and SHA-256 digests. Preview preparation and distribution verification run it and match JavaScript and CSS to current `dist/assets`. Raw storage iterators may contain compressed data; the diagnostic obtains content with `Assets::get`, the runtime decoding path. The source gate builds frontend assets before checking native production mode. This establishes compiled payload and mode, while actual desktop interaction and clean-machine installation remain separate.

## Volume counters and quotas

`voldiq-core::space` keeps whole-volume counters separate from caller allowance and availability. Measurements retain native volume GUID/serial, an optional observation date and exact serialized byte strings. Normalization checks unit multiplication, individual bounds and the storage-reserve subset; it does not invent an additive balance. Reserved space, its storage-reserve subset and pool unavailability are context fields, never extra deductions from reported used bytes.

The Windows probe pins the requested directory and ancestors, opens metadata without recall/reparse traversal, derives the volume GUID root from that handle and rechecks identity around the read. It resolves `GetDiskSpaceInformationW` through the already-loaded Kernel32 module so absent support does not add a startup import. A separate `GetDiskFreeSpaceExW` caller result may survive unavailable whole-volume counters; it never supplies a physical-used calculation. Drive scan availability retains its original access probe independently of optional counter support. Identifiers in this DTO are metadata, not mutation or agent permission. Whole-volume observations remain in the existing human desktop device surface, not scoped CLI/MCP file aggregates.

Microsoft documents the [quota-sensitive legacy totals](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw), the [whole-volume and caller fields](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-disk_space_information), and the [root-path requirement and minimum build 17763](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskspaceinformationw). Real quotas, older Windows versions, unsupported devices and hardware performance remain separate acceptance; fixture tests do not reconfigure the system.

## Indexed space reconciliation

`space::summarize` walks the current index with constant auxiliary memory and cancellation checks. Current accounting has already assigned hardlink allocation once across the index; only file records with known allocation and a matching native volume identity contribute to the known subset. Logical path bytes, recorded root allocation, cloud/recall metadata, opaque reparse records and unknown allocation remain separate evidence. Missing or unsupported accounting, absent identity, inconsistent totals and absent evidence produce unavailable states. A complete empty scope may measure zero; an unmeasured scope may not.

`space::read_desktop` binds fresh volume metadata to the captured analyzed root through native pins and a second identity check. `Report::compare` accepts only matching volume serials and subtracts known allocation from reported volume used with signed 128-bit arithmetic. Its serialized decimal result preserves negative differences. Coverage describes the recorded scope, not whole-volume coverage or physical extent uniqueness. File and volume observations can have different dates. Reserve context is never subtracted again. A scoped-only report explicitly withholds the whole-volume comparison and grants no file-operation authority.

`AgentService::space_account` uses the authorized cached snapshot, the same cancellable summary and a fresh native identity/exclusion/permission check before return. CLI `space <snapshot_id>` and MCP `voldiq_space_account` return `scoped_only` volume context and an unavailable residual, even when the root's volume could be queried. They never invoke the desktop volume reader. MCP request cancellation and CLI Ctrl+C use the existing worker lifetime and cancellation flag. Initial snapshot loading may complete before cancellation is observed; no partial report is published. No content-read, scan or operation permission follows from this metadata report.

The twelfth native query family uses the existing bounded request, index ownership and cancellation protocol. Overview opens its typed report only on demand and disposes pending ownership on context changes, close or unmount. A native metadata call can complete before observing cancellation; cancellation prevents publishing that result. No content read, hydration, background polling, system diagnosis or file executor is introduced. Native rendering, interaction and real device cases remain manual acceptance.

## Scoped CSV pages

`exports::csv` uses the existing cancellable index query and path reconstruction. Files/folders set the normalized item class; filters, ordering and offsets remain shared. At most 500 rows and 256 KiB CSV are returned per page, with an explicit continuation rather than truncation. Scope observation/accounting, incomplete coverage, exclusion count, units and exact decimal data remain in the envelope. Names are captured display strings; path exactness is reported when paths are explicitly requested. Default output omits full paths and the scope-root path.

All name/path cells have a literal `text: ` prefix and RFC-style quote escaping. The prefix is data, not an escape character to remove in spreadsheet workflows. Numeric values retain exact digits in the CSV; spreadsheet imports should treat large integers as text. `AgentService::export_csv` requires Metadata and Export, applies the principal's page cap and repeats Export permission and native scope authorization before return. CLI/MCP cancellation returns no partial page and worker ownership remains bounded. No filesystem destination, file content, note, credential or operation permission is accepted by this export. Complete desktop CSV saving uses the separate native workflow below; other formats remain pending.

## Complete CSV streaming

`exports::stream_csv` is the complete-report encoder for the human file exporter. Its filter type omits sort/pagination and projects into the same compiled predicate evaluator. It visits recorded index order, excludes the structural root and does not collect a matching-row vector. The caller supplies `Write`; only one encoded row, filter/path working state and small metadata records are added to the already-loaded index. No file is opened or published by this encoder and it is not exposed as an agent destination-writing endpoint.

The complete report has eleven columns: record type, the nine shared item columns and context JSON. A `scope` record carries schema version, measurement/generation dates, filter, item class, coverage/unknowns, units, path consent, record order and limitations. `item` records share the page encoder's literal text prefix/escaping. A `complete` record contains inspected/emitted counts, including an empty result. Consumers must parse CSV records rather than line-split names containing newlines. Encoder completion is distinct from flushing, durability and safe destination publication. Cancellation returns an explicit cancelled outcome and may leave a prefix; I/O/filter errors can also leave a prefix. A persistent adapter must publish only successful complete output after its own flush/revalidation. Progress reports inspected and emitted counts, throttled between blocks plus start/final callbacks; the native transport coalesces it into one latest value.

## Native complete CSV workflow

`CsvExport.svelte` adds a compact modal from the loaded analysis's heading. Files/folders, recursive current-folder/whole-analysis scope, applied filters and full-path/filter-text consent are explicit. UI sort and pagination are omitted from the stream request. The native `save_csv_report` command receives no destination path: it reserves one session, opens the installed native save dialog, acquires the shared operation guard and verifies the captured analysis identity before filesystem work. The blocking worker retains the session, index read guard and operation lease until safe core publication or cleanup returns.

Only one latest progress value is stored. `csv_report_progress` reads it by request UUID and analysis ID. The frontend uses one outstanding pull, at most every 250 ms after settlement, exclusively during the pending command. Cancellation is likewise matched to the session and uses the operation's existing atomic token during generation. A stop during the chooser is remembered; the native dialog must still return before the command settles. Session Drop clears only its own slot, including errors/unwinding. The final command receipt, rather than a progress count, establishes completion. The frontend discards late progress, verifies final receipt ownership, and stops timers after settlement. Disposal requests cancellation and keeps only the existing bounded pull until that command settles, covering cancellation before session registration.

Both CSV pages and whole-file scope metadata now withhold nonempty literal text, expression and extension filter strings unless `include_paths` is true. These strings can themselves contain paths or URLs. They become JSON null, with `filter_text_included=false`; empty strings and numeric/enum predicates remain explicit. Query matching still uses the original values. The human control therefore names both full paths and filter text; agent clients must opt in explicitly too. This changes only exported metadata, not query semantics or permission. Redacted metadata is not a replayable query specification. Native dialogue interaction, visual/focus/keyboard/scaling and device acceptance remain manual.

## Windows CSV destination ownership

`exports::save_csv` is a human-adapter API that borrows the existing operation lease. It reads fresh folder protections from that lease's pinned state directory, rejects sensitive/system/state/protected destinations and pins the chosen ordinary parent and ancestors. It creates a random private temporary file relative to a checked parent handle using create-only native semantics and exclusive sharing. The protected DACL permits the current user and administrators; unsupported security/identity evidence fails instead of falling back to a broadly readable file.

The complete encoder writes through a bounded buffer. Publication requires Complete, flushing, a successful file sync, current destination permissions, refreshed protections, retained parent/ancestor evidence, full temporary file identity, a matching DACL and no reparse/recall/multiple-link state. A handle-relative `NtSetInformationFile(FileRenameInformation)` rename leaves ReplaceIfExists false. An existing destination, including one created during generation, is never opened for writing or replaced. The output retains the private DACL. A successful sync request is not a power-loss guarantee for every device or filesystem.

The owned fixture rejected the initial Win32 rename form with error 87 at publication. This exporter therefore uses the native rename contract already used by protected staging, rather than a retry or pathname fallback. The [native information-class contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/content/ntifs/nf-ntifs-ntsetinformationfile) defines FileRenameInformation as class 10; it must not be confused with Win32 class 3. This observation does not establish that every Win32 relative rename is unsupported.

Cancellation and ordinary errors mark only the exclusively retained newly created file handle for deletion. There is no pathname-based deletion fallback. Explicit cleanup failure reports uncertainty; Drop also makes a best-effort attempt for unwinding. Process termination can leave a private temporary file. Unknown remnants are never purged or reused automatically. No CLI/MCP destination-writing endpoint is exposed. The native save-dialog, scope and progress workflow is described above.

## Read-only Windows recovery discovery

`recovery::read_desktop` binds a local `Win32_ShadowCopy` WMI query to the captured root's checked metadata handle and native volume GUID. It holds the existing directory/ancestor pins and rechecks identity after the provider returns. The full GUID path helper is shared with volume accounting; caller availability still uses the original directory scope. Root replacement or unavailable native evidence discards the discovery. This volume-wide API is not exposed through scoped agent services, CLI or MCP.

The installed `windows` 0.62.2 dependency supplies COM, WMI and variant bindings. An owned same-thread MTA apartment outlives all interfaces and property variants. Local `ROOT\CIMV2` uses the current principal and authenticated private proxies; no remote endpoint, credential, arbitrary query or process-wide security configuration is accepted. The fixed query selects only created VSS records for the exact volume. Scalars are type-checked, strings bounded, GUIDs validated and duplicate IDs rejected. Variants clear on every exit; interface disposal precedes `CoUninitialize`. No writer event, copy creation, deletion, exposure or file read is requested.

Enumeration retains at most 100 records and reads at most 101. `Next` waits at most 100 ms per call, with cooperative cancellation and a five-second enumeration window checked between rows. COM connection, query and property calls may finish before cancellation or the window is observed; this is not an end-to-end latency guarantee. Complete enumeration, item/time limits, access denial, missing provider, invalid metadata and native failure are distinct. An empty limited result never establishes an empty catalogue. Optional installation dates use fully specified CIM offsets at second precision; wildcards, missing dates and invalid metadata stay unknown. Provider/access/persistence metadata does not prove that a particular file exists or can be restored. Storage consumption is not measured or deducted by this catalogue.

Microsoft documents the [shadow-copy records](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/vsswmi/win32-shadowcopy), [enumeration completion versus timeout](https://learn.microsoft.com/en-us/windows/win32/api/wbemcli/nf-wbemcli-ienumwbemclassobject-next), [proxy security](https://learn.microsoft.com/en-us/windows/win32/wmisdk/setting-the-security-on-iwbemservices-and-other-proxies) and [CIM date representation](https://learn.microsoft.com/en-us/windows/win32/wmisdk/cim-datetime). `IVssSnapshotMgmt::QuerySnapshotsByVolume` is [reserved for system use](https://learn.microsoft.com/en-us/windows/win32/api/vsmgmt/nn-vsmgmt-ivsssnapshotmgmt), so it is not used. Privileged/populated providers, other backup mechanisms and reviewed no-overwrite restoration remain subsequent acceptance/work.

The native recovery adapter uses the thirteenth bounded query family with the existing index/session/request ownership and cancellation protocol. Overview opens its typed report explicitly, invalidates displaced owners, cancels on close/context change/disposal and restores displaced control focus only for its current owner. The report always describes the analyzed root's containing volume, independently of the selected-drive picker or current map folder. Complete-empty, limited-empty and unavailable results have separate presentation. Catalogue IDs never become native file-action IDs. This control does not request elevation or expose volume discovery to agents. Rendered composition and native interaction remain manual acceptance.

## Explicit Live observation sessions

The Windows `voldiq-core::live::Session` owns one asynchronous directory notification, the root/ancestor and exclusion metadata pins, a 32 KiB DWORD-aligned buffer and a stable `OVERLAPPED` allocation. It is created and used by its owning worker only after explicit activation. A cloneable `Control` signals stop or resynchronization from another thread. There is no background thread, idle timer, retained path-event queue or automatic history write in the core session. The native adapter below owns its worker and publication lifetime.

The notification is armed before an initial full rescan, closing the activation gap. Subsequent invalidations coalesce for a fixed 300 ms window. Notifications are hints, not file operations or reliable per-file change records. Zero transferred bytes and `ERROR_NOTIFY_ENUM_DIR` request full resynchronization. Every observation reuses the existing directory scanner with the captured exclusions, rechecks pinned identities and returns a replacement index. It never patches sizes from event names or relies on a possibly incomplete USN replay. Changes during a scan remain buffered for a subsequent observation. Excluded-directory notifications can trigger another scan, but excluded entries remain outside its measurement.

Reports keep both observation dates, coverage and accounting revision. Logical byte strings and signed net change stay exact. A partial, unknown or incompatible baseline has no known delta. These are non-atomic filesystem observations, not physical writes, observed volume free-space change or attribution to a process. Unsupported notifications, unavailable pins and changed evidence fail explicitly. Stop wakes an idle wait and cooperatively cancels an active scan. Drop requests cancellation and drains the terminal I/O completion before freeing its buffers, events or namespace pins.

The native API contracts are documented by Microsoft for [directory notifications](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw) and [cancellation completion](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex). This implementation keeps one pending read and re-arms it before returning a batch; repeated immediate overflow errors stop the session instead of spinning.

The native adapter holds the shared operation lease for an explicitly started session and publishes replacements through `Engine::publish`. A one-slot acknowledgement channel prevents another observation from replacing the index before the frontend processes the preceding one. The run retains only that publication's previous/current pair for navigation rebasing. A directory must uniquely match its native identity in compatible root/exclusion scopes; local node numbers are never carried across indexes. One owned in-memory navigation permit bounds that lookup until its blocking worker exits. Stop closes the only acknowledgement sender and signals the core control, waking either wait. Terminal delivery follows core worker disposal and lease release. Page reload, destroyed/hidden/minimized windows and frontend visibility/disposal request shutdown; no Live preference is persisted.

The frontend session controller owns startup, native events, acknowledgement and stop intents. It adopts a final publication even when stop races delivery, waits for adoption/refresh before acknowledging, ignores old owners and closes a late startup result after disposal. Native callbacks and start responses may arrive in either order. The existing index-context boundary invalidates stale queries and selections; an adopted frame keeps the current root and rebinds folder navigation through the temporary publication pair. Read-only history remains available while file operations and competing analyses wait for Stop Live. Native rendering and real window-event/keyboard/scaling behavior remain separate manual acceptance.
